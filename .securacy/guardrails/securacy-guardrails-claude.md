### SC-4 · API authorization & injection
_Applies on endpoint / query changes._

**Never write:**

- ✗ Build a SQL/NoSQL query by string concatenation or f-string interpolation of request data — use parameterized queries.
- ✗ Authorize using a client-supplied user/tenant/resource id — resolve ownership from the authenticated principal.
- ✗ Bind a request body to a model without an explicit field allowlist (mass assignment).

**Verify:**

- Confirm every query you touched is parameterized.

**Criteria:**

- [ ] No unparameterized query introduced

### SC-11 · Web input/output safety
_Applies on web handler / template / form changes._

**Never write:**

- ✗ Render untrusted input via `innerHTML`/`dangerouslySetInnerHTML` or an unescaped template — always escape or use safe DOM APIs.
- ✗ Add a state-changing endpoint without CSRF protection (token or SameSite cookie).
- ✗ Interpolate request data into a SQL/OS/template expression — use parameterized queries and safe builders.

**Verify:**

**Criteria:**

- [ ] CSRF protection present on state-changing routes added

## Completion report — `securacy-report:v2`

Report on **controls** (the IDs like `T005.C1` above), not just rules. The Securacy CI check reads only the IDs, statuses and file locations, never free text.

**Control statuses:**

- `IMPLEMENTED` — the control is in the code. Evidence: the file and lines that implement it (you read them; you did not assume).
- `FIXED` — the control was missing and this change adds it. Evidence: the changed file and lines.
- `MISSING` — the control is not in the code. Evidence, if there is one: the file that handles this component, where the control belongs.
- `REGRESSED` — the rule's **State** shows the control in place and this change removes or weakens it. Evidence: the changed file and lines.
- `NOT_APPLICABLE` — no code in this repository implements this kind of control (it is owned elsewhere, or the infrastructure lives in another repository).

**Never pattern statuses** (`never`, the IDs like `T005.N1` above):

- `PRESENT` — specific lines do the forbidden thing themselves (a hardcoded secret, a secret printed to a log). Evidence: those lines.
- `ABSENT` — no line does it. An attack that works only because a control is missing is that control's `MISSING`, not a `PRESENT` pattern.
- `RESOLVED` — the rule's **State** marks the pattern ! and this change removes it. Evidence: the changed file and lines.

**Two kinds of run:**

- **Full sweep** (`"mode": "sweep"`): give every control and every Never pattern of every rule a status.
- **Change check** (`"mode": "diff"`): report only the controls and Never patterns the change touches: changed files that implement a ✓ control, should implement a ✗ one, or hold a ! pattern. Leave the rest out; their state carries over.

When a change adds code matching one of a rule's own **Never** patterns, report that pattern `PRESENT` with the changed lines. Set `"introduced": true` on a rule, with evidence, when the change adds code matching a cited `SC-*` ✗ pattern. Evidence `path` is relative to the repository root and `lines` is `"12"` or `"12-18"`. `component_map` maps names from the **Component map** to the paths that implement them; use only names listed there.

**Design changes** (`design_changes`): parts of the system's design that match nothing in the **Component map** or its **Design inventory**.
